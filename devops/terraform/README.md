# LaunchDarkly Terraform — Guarded Release Demo

Manages the LaunchDarkly flag + metrics that drive this repo's Guarded Release
demo as code, using the **LaunchDarkly Terraform provider v3**.

All of these resources were created **by hand in the LD UI first**, then imported
into Terraform state so the config below is the source of truth going forward.
The account is shared with the AVTA / AppleMusicPlaylist project (LD project
`default`), and the API key is read from that project's `.env`.

## Files

| File | Manages |
|---|---|
| `main.tf` | Provider `launchdarkly/launchdarkly ~> 3.0`, variables (project `default`, env `production`). |
| `flags.tf` | `new-checkout-flow` boolean flag + its `production` environment config. Every branch of the demo evaluates this flag. |
| `metrics.tf` | The two Guarded-Release metrics, one per ingestion style the branches show. |
| `import.sh` | One-time: imports the 4 pre-existing resources into state. |
| `apply.sh` | `init` + `plan` + `apply`. Reads `LD_API_KEY` from the AVTA `.env`. |

## Resources (all imported — none created by Terraform)

| Terraform address | LD key | Notes |
|---|---|---|
| `launchdarkly_feature_flag.new_checkout_flow` | `new-checkout-flow` | Boolean. false=old checkout (v1), true=new checkout (v2, slow+flaky). |
| `launchdarkly_feature_flag_environment.new_checkout_flow_production` | — | Production: on, default rule serves `false`. |
| `launchdarkly_metric.checkout_latency` | `checkout-latency` | Numeric ms, avg, lower-is-better. Fed by `LdClient.Track()` — branch `no-otel-use-sdk-metric`. |
| `launchdarkly_metric.http_latency_checkout` | `http-latency-checkout` | Numeric ms, avg, lower-is-better. Wraps OTel event `http.latency;route=/api/checkout` — branches `main`, `otel-integration*`. |

### Which metric per branch

| Branch | Metric ingestion | Monitored metric |
|---|---|---|
| `main`, `otel-integration`, `otel-integration-fan-out` | LD Observability / OpenTelemetry auto event | `http-latency-checkout` |
| `no-otel-use-sdk-metric` | Pure SDK `LdClient.Track()` | `checkout-latency` |

## First-time setup (already done for this repo)

State is already imported and in sync. If you clone fresh or lose state, rebuild it:

```bash
bash import.sh          # imports flag + env + 2 metrics into a new state file
terraform plan -var "ld_api_key=$LD_API_KEY"   # expect: No changes
```

`import.sh` reads `LD_API_KEY` from `~/source/personal/AppleMusicPlaylist/server/.env`
by default. Override with `LD_API_KEY=api-xxxx bash import.sh` or point
`LD_ENV_FILE` at another `.env`.

## Ongoing changes

```bash
bash apply.sh           # init + plan + apply
```

Edit `flags.tf` / `metrics.tf`, run `apply.sh`, and Terraform reconciles LD to
match. A clean `plan` (`No changes`) means live LD and this config agree.

## What is NOT in Terraform

- **The Guarded Rollout / auto-rollback configuration** on the flag's default rule.
  The v3 provider has no resource for a guarded rollout, so start it in the LD UI
  (flag → Targeting → default rule → Guarded rollout, target `true`, monitor one of
  the metrics above, enable auto-rollback). See the branch READMEs for the exact steps.
- **Autogenerated Observability/OTel/AI metrics** (`ld_autogen__*`) — LD creates
  and owns these automatically from telemetry; do not manage them here.
