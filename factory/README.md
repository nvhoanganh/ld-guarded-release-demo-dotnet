# factory/ — Beacon deploy (Render)

Deploys **Beacon** (AutoFactory Phase 2 release orchestrator) as a Render web
service. Beacon receives deploy notifications, discovers newly-added release
flags in `.release-flags/`, and starts + monitors the guarded release in
LaunchDarkly.

Beacon's source lives in the [`launchdarkly-auto-factory`](https://github.com/nvhoanganh/launchdarkly-auto-factory)
monorepo (it depends on the `@auto-factory/shared` workspace). Rather than vendor
that code, the `Dockerfile` here **clones the repo at a pinned commit** and builds
the beacon package. Bump `AUTOFACTORY_SHA` in the Dockerfile to move it forward.

## Files

| File | Purpose |
|---|---|
| `Dockerfile` | Clones auto-factory @ pinned SHA, builds beacon, runs `packages/beacon/dist/server.js`. |
| `render.yaml` | Render Blueprint: web service + persistent disk + env vars. |
| `.env.example` | The runtime env (for local `docker run` or reference). |

## Deploy to Render

1. Render → **New → Blueprint** → pick this repo. Render reads `factory/render.yaml`.
2. After the first build, set the `sync: false` secrets in the dashboard:
   - `GITHUB_TOKEN` — fine-grained, **read-only Contents** on the onboarded repo(s).
   - `LD_API_KEY` — `api-…`, scoped to the **app** project.
   - `LD_PROJECT_KEY` — the app project key.
3. `BEACON_WEBHOOK_SECRET` is auto-generated by Render — copy its value from the
   dashboard; you'll give the same value to whatever POSTs deploys.
4. Health check: `GET https://<service>.onrender.com/health` → `{ "ok": true }`.

Port: Render injects `PORT`; Beacon binds it automatically — don't hardcode it.

State: `render.yaml` mounts a 1 GB disk at `/data` and points
`BEACON_STATE_FILE` there, so last-seen-SHA tracking survives restarts.

## Run locally

```bash
docker build -t auto-factory-beacon ./factory
cp factory/.env.example beacon.env   # fill in values
docker run -p 8080:8080 --env-file beacon.env auto-factory-beacon
curl localhost:8080/health
```

## Wire the demo app (Railway) to this Beacon

The .NET app in this repo deploys to Railway (root `Dockerfile` + `railway.json`)
and exposes `GET /api/status` → `{ "version": "<deployed-sha>" }`.

1. Register the app in the auto-factory repo's `config/services.yaml`:

   ```yaml
   services:
     guarded-release-demo:
       side: backend
       repo: nvhoanganh/ld-guarded-release-demo-dotnet
       statusUrl: https://<your-railway-app>.up.railway.app/api/status
       statusShaField: version
   ```

   (`services.yaml` is baked into the Beacon image at build time via the clone —
   commit the entry upstream, then bump `AUTOFACTORY_SHA` to pick it up.)

2. Notify Beacon after each Railway deploy — either a Railway deploy webhook to
   `https://<beacon>.onrender.com/webhooks/railway?secret=<BEACON_WEBHOOK_SECRET>`,
   or a generic POST:

   ```bash
   curl -X POST https://<beacon>.onrender.com/flag-releases \
     -H "x-beacon-secret: $BEACON_WEBHOOK_SECRET" \
     -H "content-type: application/json" \
     -d '{"service":"guarded-release-demo","sha":"<deployed-sha>"}'
   ```
